## 작동 방식

MMU가 TLB에서 해당 주소 공간의 페이지 번호를 찾으면 캐시된 변환과 접근 권한을 확인합니다. TLB miss라면 페이지 테이블에서 매핑과 권한을 확인하고, 유효한 변환을 TLB에 채운 뒤 메모리에 접근합니다. TLB hit여도 접근 권한 검사를 생략하지 않습니다.

### 예시로 확인하기

반복문이 같은 페이지의 배열을 읽으면 TLB hit가 반복되어 테이블 조회를 줄입니다. 다른 프로세스로 전환하면 주소 공간이 바뀌어 TLB 일부를 비우거나 태그해야 합니다.

### 설계에서의 선택

TLB는 변환 지연을 줄이지만 작고 비싼 캐시라 모든 페이지를 담지 못합니다. 페이지 크기를 키우면 TLB 도달 범위가 늘지만 내부 단편화가 증가할 수 있습니다.
