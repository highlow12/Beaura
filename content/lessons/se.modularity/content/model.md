# 응집도와 결합도 읽기

응집도가 높은 모듈에서는 함수와 자료가 같은 업무 개념을 설명합니다. `Invoice` 모듈이 항목 추가, 합계 계산, 세금 계산을 담당한다면 서로 관련된 규칙이 가까이 있어 이해하기 쉽습니다. 반대로 결제, 이미지 크기 조절, 이메일 전송이 한 모듈에 섞이면 각 변경 이유가 달라 응집도가 낮습니다.

결합도는 단순히 import 개수만 세는 값이 아닙니다. 다른 모듈의 내부 자료 구조를 직접 만지거나, 호출 순서와 전역 상태를 암묵적으로 요구하면 결합도가 커집니다. 값과 의미가 분명한 인터페이스를 통해 필요한 동작만 요청하면 내부 변경이 경계를 덜 넘어옵니다.

경계를 정할 때는 데이터의 소유자와 변경의 방향을 먼저 적어 봅니다. 소유 모듈이 불변 조건을 지키고, 외부에는 명령과 결과를 제공하도록 설계하면 결합을 줄일 수 있습니다. 작은 모듈을 무조건 많이 만드는 것도 답은 아니므로 호출 흐름이 읽히는지, 테스트가 독립적인지도 함께 확인해야 합니다.
