# 변경 이력을 다루는 법

버전 관리는 파일의 현재 상태만 저장하는 도구가 아니라 시간에 따른 변경의 의미와 순서를 보존하는 시스템입니다. 커밋은 검토하고 되돌릴 수 있는 하나의 논리적 스냅샷이고, 메시지는 왜 변경했는지를 미래의 협업자에게 설명합니다. 작고 일관된 커밋은 문제를 찾고 선택적으로 되돌리기 쉽습니다.

브랜치는 특정 커밋을 가리키는 이동 가능한 이름으로, 독립적인 작업 흐름을 만들 수 있게 합니다. 브랜치가 있다고 해서 변경이 자동으로 격리되는 것은 아닙니다. 작업 중인 파일, 공유된 기반 커밋, 병합 시점을 명확히 관리해야 다른 작업을 안전하게 통합할 수 있습니다.

병합은 두 이력의 변경을 하나의 결과로 합치는 과정입니다. 서로 다른 줄을 바꾸면 자동으로 합쳐질 수 있지만 같은 부분을 다르게 수정하면 충돌이 생깁니다. 충돌은 도구가 임의로 결정할 문제가 아니라 두 의도를 읽고 선택한 뒤 테스트로 확인할 문제입니다.
