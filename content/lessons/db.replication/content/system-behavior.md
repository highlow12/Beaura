## 복제본은 백업과 다르다

복제는 보통 primary의 변경을 replica에도 재생하는 기능입니다. 따라서 잘못된 `DELETE`나 버그 난 UPDATE도 정상적인 변경으로 간주되어 replica에 전파될 수 있습니다.

```sql
-- primary에서 실행한 실수
DELETE FROM UserProfile WHERE id = 7;
```

비동기 replica가 잠시 뒤처져 있다면 짧은 시간 동안 옛 행을 볼 수 있지만, 따라잡은 뒤에는 삭제된 상태가 됩니다. 장애 시 빠르게 읽기·쓰기 역할을 넘기는 데는 유용해도, 과거 시점으로 돌아갈 독립적인 기록을 제공하지는 않습니다. 이를 위해 정기적인 전체 백업과 보존 기간이 있는 WAL 또는 변경 로그를 별도로 운영해 point-in-time recovery를 준비합니다.

### 자주 틀리는 포인트

“replica가 있으니 백업이 있다”거나 “failover하면 실수한 데이터를 되돌릴 수 있다”고 생각하면 안 됩니다. 복제는 가용성과 읽기 확장을 위한 현재 상태의 사본이고, 백업은 논리적 실수와 저장 장치 손실에 대비한 과거 상태의 복구 수단입니다. 두 시스템의 보존 기간과 복구 목표(RPO·RTO)를 따로 확인해야 합니다.
