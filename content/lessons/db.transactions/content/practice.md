## 트랜잭션 경계 정하기

트랜잭션을 너무 넓게 잡으면 잠금과 대기 시간이 늘고, 너무 잘게 나누면 중간 상태가 노출되거나 여러 작업을 함께 되돌릴 수 없습니다. 한 업무 규칙을 깨뜨릴 수 없는 최소 단위를 경계로 삼고, 외부 API 호출처럼 오래 걸리는 작업은 DB 잠금 안에 불필요하게 넣지 않는 것이 좋습니다.

commit 뒤에는 클라이언트가 성공 응답을 받기 전에 프로세스가 종료되더라도 결과를 보존해야 합니다. DBMS는 로그와 저장 장치 동기화 같은 내부 기법으로 이를 지원하지만, 애플리케이션은 오류 경로에서 반드시 rollback 또는 재시도 정책을 명확히 해야 합니다.
