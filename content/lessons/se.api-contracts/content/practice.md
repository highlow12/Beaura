## 계약을 문장과 테스트로 고정하기

페이지 조회 API를 설계한다면 “`limit`은 1 ~ 100의 정수여야 한다”를 사전 조건으로, “성공하면 요청한 범위를 넘지 않는 항목과 `next_cursor`를 반환한다”를 사후 조건으로 적습니다. 인증 실패와 잘못된 입력의 오류 형태도 계약의 일부이므로 상태 코드와 메시지의 의미를 함께 정합니다.

호출자와 구현자의 책임을 섞지 않도록 경계를 만드세요. 호출자 입력은 경계에서 빠르게 검증하고, 내부 로직은 검증된 상태라는 가정을 사용할 수 있습니다. 다만 저장소나 외부 서비스의 응답은 신뢰할 수 없으므로 어댑터 경계에서 다시 변환하고 예상 밖 형태는 명확한 오류로 처리합니다.

문서만으로 계약이 살아 있지는 않습니다. 정상 입력, 경계값, 잘못된 입력, 재시도 상황을 테스트로 고정하고, 테스트 이름에 보장하려는 규칙을 담으세요. 구현을 바꾼 뒤에도 같은 계약 테스트가 통과하면 내부 자유와 외부 안정성을 함께 얻을 수 있습니다.
