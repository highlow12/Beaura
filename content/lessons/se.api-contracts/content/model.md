# 사전 조건과 사후 조건

사전 조건(precondition)은 작업을 호출하기 전에 참이어야 하는 조건입니다. 입력 범위, 인증 여부, 객체의 현재 상태 등이 여기에 들어갑니다. 사후 조건(postcondition)은 성공적으로 끝난 뒤 시스템이 보장해야 하는 결과입니다. 반환 형식, 저장된 상태, 부수 효과의 횟수를 구체적으로 적을 수 있습니다.

불변식(invariant)은 작업 전후에 계속 유지되어야 하는 규칙입니다. 은행 계좌의 잔액이 허용 범위를 벗어나지 않아야 한다거나, 주문의 항목 수가 음수가 아니어야 한다는 식입니다. 여러 API가 같은 불변식을 공유하면 각 경계에서 검증하고 내부 상태가 깨진 채 퍼지지 않게 해야 합니다.

계약을 변경할 때는 호환성을 살핍니다. 새 버전이 기존 호출의 유효한 입력을 거부하거나, 성공 응답의 의미를 바꾸거나, 기존 오류 처리를 다른 방식으로 만들면 하위 호환성이 깨집니다. 확장 필드는 선택적으로 추가하고, 제거·의미 변경은 명시적인 버전 정책과 함께 다루는 편이 안전합니다.
