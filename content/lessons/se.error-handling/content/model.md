# 복구와 전파의 경계

입력 검증 오류는 보통 요청 경계에서 구조화된 오류 응답으로 바꿉니다. 반면 데이터베이스 연결이 잠시 끊긴 것처럼 재시도 가능한 오류는 제한된 횟수와 지수 백오프로 다룰 수 있습니다. 재시도 전에 작업이 멱등적인지 확인하지 않으면 같은 결제가 여러 번 실행되는 부작용이 생깁니다.

하위 계층은 자신이 아는 원인을 보존해야 합니다. 파일 계층이 `FileNotFoundError`를 잡아 “실패”라는 일반 문자열만 반환하면 상위 계층은 새 파일 생성, 사용자 안내, 장애 경보 중 무엇을 선택해야 할지 알 수 없습니다. 필요한 경우 도메인 오류로 변환하되 원인과 식별 가능한 맥락은 연결해 둡니다.

예외를 잡는 범위는 좁게 유지하세요. 넓은 `except`로 모든 오류를 무시하면 버그와 예상된 실패를 구분할 수 없고 시스템이 잘못된 상태로 계속 실행될 수 있습니다. 복구할 수 없는 오류는 시작 단계나 불변식 검사에서 즉시 중단하고 운영자가 알아차릴 신호를 남깁니다.
