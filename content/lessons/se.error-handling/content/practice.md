## 오류 흐름을 그려 보기

결제 요청을 예로 들면 입력 형식 오류는 클라이언트에 4xx와 수정 가능한 필드를 반환하고, 결제 제공자의 일시적 타임아웃은 멱등 키를 사용해 제한적으로 재시도할 수 있습니다. 제공자가 결제 결과를 모호하게 반환했다면 성공으로 가정하지 말고 조회나 보류 상태로 전환해야 합니다.

코드에서는 `try` 블록에 실제로 복구할 작업만 넣고, `except`에서 예상한 예외만 잡습니다. 로그에는 요청 ID, 작업 이름, 재시도 횟수 같은 구조화된 필드를 기록하되 카드 번호나 토큰은 제거합니다. 상위 계층으로 전파할 때는 사용자에게 보여 줄 안전한 메시지와 내부 원인을 분리합니다.

테스트는 정상 경로만 확인하지 않습니다. 잘못된 입력, 재시도 횟수 초과, 중복 실행, 취소와 타임아웃의 경계를 각각 재현하세요. 각 오류가 복구·전파·실패 중 어느 정책으로 끝나는지 표로 적어 두면 코드 리뷰에서 숨은 가정을 찾기 쉽습니다.
