# 장애 뒤의 데이터 상태

DBMS는 프로세스나 전원이 중단되어도 commit된 변경은 보존하고 commit되지 않은 변경은 되돌려야 합니다. 이를 위해 변경된 데이터 페이지를 디스크에 기록하기 전에 관련 로그를 먼저 안전하게 저장하는 Write-Ahead Logging(WAL) 같은 규칙을 사용합니다. commit 성공을 응답하기 전에는 commit 사실을 복구할 수 있도록 로그의 내구성을 확보해야 하지만, 변경된 데이터 페이지 자체는 그 뒤에 디스크에 기록해도 됩니다.

복구기는 마지막 checkpoint와 로그를 기준으로 어떤 트랜잭션을 재실행(redo)하고 어떤 미완료 변경을 취소(undo)할지 판단합니다. checkpoint는 전체 로그를 매번 처음부터 읽지 않도록 복구 시작 지점을 줄이는 표식이지, 모든 변경이 그 순간 디스크에 완결됐다는 뜻과 항상 같지는 않습니다.
