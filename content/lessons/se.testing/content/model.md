# 세 종류의 범위

단위 테스트는 함수나 클래스처럼 작은 단위를 격리해 빠르게 검증합니다. 입력과 반환값, 상태 변화 같은 계약을 집중적으로 다루므로 실패 원인을 찾기 쉽습니다. 단위의 경계는 파일 하나와 같을 필요가 없으며, 한 책임을 독립적으로 판단할 수 있는 크기면 됩니다.

통합 테스트는 저장소, 메시지 큐, 여러 모듈처럼 실제 경계가 함께 연결되는지를 확인합니다. 단위 테스트가 놓치는 직렬화·쿼리·설정 문제를 잡는 대신 환경 준비와 실행 비용이 커집니다. E2E 테스트는 브라우저나 API에서 시작해 사용자에게 중요한 전체 흐름을 검증하지만 실패 지점이 넓고 느립니다.

테스트 더블에는 목적이 있습니다. stub은 미리 정한 값을 반환하고, fake는 가벼운 동작 구현을 제공하며, mock은 특정 호출을 검증합니다. 더블을 많이 쓸수록 외부 시스템과의 통합 계약을 별도 테스트로 보충해야 실제 동작과 가짜 동작의 차이를 놓치지 않습니다.
