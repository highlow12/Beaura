# 테스트의 역할

테스트는 코드를 대신 실행해 주는 장식이 아니라, 시스템이 지켜야 할 관찰 가능한 규칙을 빠르게 확인하는 예입니다. 좋은 테스트는 무엇을 보장하는지 드러내고, 실패했을 때 문제의 위치를 좁혀 줍니다. 구현 세부의 모든 줄을 복사하듯 검증하면 작은 리팩터링에도 테스트가 함께 깨집니다.

테스트 피라미드는 빠르고 좁은 단위 테스트를 아래에 많이 두고, 여러 모듈을 묶는 통합 테스트와 사용자 흐름을 검증하는 E2E 테스트를 위로 갈수록 적게 두는 전략입니다. 이는 절대 규칙이 아니라 실행 비용과 피드백 속도의 차이를 반영한 균형점입니다.

테스트는 결정적이어야 합니다. 현재 시각, 난수, 네트워크, 공유 데이터베이스에 직접 기대면 같은 코드도 실행마다 결과가 달라질 수 있습니다. 외부 경계는 작은 테스트 더블이나 고정된 픽스처로 통제하고, 실제 연결이 필요한 검사는 별도 계층으로 분리하세요.
