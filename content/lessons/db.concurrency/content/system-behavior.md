## 버전 비교로 낙관적 충돌을 감지하기

잠금을 오래 잡기 어려운 화면 편집에서는 행의 버전을 함께 비교하는 낙관적 동시성 제어를 사용할 수 있습니다. 두 사용자가 `version = 3`을 읽었다면, 먼저 저장한 요청만 조건을 만족해 버전을 4로 올립니다.

```sql
-- 두 요청이 모두 version 3을 읽었다고 가정
UPDATE Document
SET body = '첫 번째 저장', version = version + 1
WHERE id = 9 AND version = 3;
-- 영향받은 행 1개: 저장 성공, version 4

UPDATE Document
SET body = '두 번째 저장', version = version + 1
WHERE id = 9 AND version = 3;
-- 영향받은 행 0개: 이미 다른 저장이 있었으므로 충돌
```

두 번째 요청은 무조건 덮어쓰지 않고 최신 내용을 다시 읽어 사용자에게 병합이나 재시도를 요청합니다. 충돌이 드문 편집 화면에서는 잠금 대기 없이 처리할 수 있지만, 충돌이 잦으면 재시도 비용과 사용자 경험이 나빠집니다. 이때는 짧은 트랜잭션과 잠금을 쓰는 비관적 방식이 더 적절할 수 있습니다.

### 자주 틀리는 포인트

버전 조건을 `WHERE`에 넣고도 UPDATE의 영향받은 행 수를 확인하지 않으면 충돌 감지가 사라집니다. 또한 먼저 `SELECT`로 확인했다는 이유만으로 나중의 무조건적인 UPDATE가 안전해지는 것은 아닙니다. 읽기와 쓰기 사이에 다른 트랜잭션이 끼어들 수 있다는 전제를 유지하세요.
