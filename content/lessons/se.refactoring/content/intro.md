# 리팩터링이란 무엇인가

리팩터링은 외부에서 관찰되는 동작을 보존하면서 코드의 내부 구조를 개선하는 작업입니다. 이름을 명확하게 바꾸고, 중복을 제거하고, 한 함수에 몰린 책임을 나누는 변화가 대표적입니다. 기능 추가나 버그 수정과 섞이면 무엇이 바뀌었는지 확인하기 어려우므로 목적을 구분해 기록하는 편이 좋습니다.

리팩터링의 대상은 코드 냄새(code smell)입니다. 너무 긴 함수, 반복된 조건, 서로 다른 책임의 결합, 의도를 숨기는 이름은 당장 실패를 일으키지 않아도 변경 비용을 키웁니다. 냄새는 자동으로 잘못된 코드라는 판정이 아니라 어디를 읽고 질문할지 알려 주는 신호입니다.

안전한 리팩터링은 작은 단계와 빠른 피드백을 사용합니다. 기존 동작을 설명하는 테스트를 먼저 확보하고, 한 번에 한 구조만 바꾼 뒤 테스트와 diff를 확인합니다. 컴파일이 된다는 것만으로 동작 보존을 증명할 수 없으므로 경계값과 중요한 부수 효과도 살펴야 합니다.
