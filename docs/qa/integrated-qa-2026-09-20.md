## 발견 및 수정

### QA-001 백업 복원 시 오늘 XP 축소

- 심각도/확신도: 높음 / 높음
- 재현 조건: 같은 밀리초에 다수의 학습 이벤트를 만든 뒤 백업을 두 번 복원
- 기대 동작: 누적 XP, 오늘 XP, 진행 상태가 복원 전과 동일
- 실제 동작: 누적 XP는 유지되지만 오늘 XP가 `3,750`에서 `750`으로 축소
- 영향: 장기 기록 복원 후 일일 목표와 오늘 학습량이 잘못 표시됨
- 원인: 같은 `createdAt`을 가진 게임 이벤트를 ID 문자열 순으로 재생했다. ID 사전순은 원래 학습 순서와 일치하지 않아 중간 `todayXp` 스냅샷이 마지막 값이 될 수 없었다.
- 수정: 연결된 StudyEvent의 `clientSeq`로 게임 이벤트를 정렬하고, 동일 학습 이벤트에서는 streak 스냅샷을 XP 이벤트보다 먼저 재생
- 회귀 테스트: 500문제 학습 데이터 생성→백업→2회 복원 후 snapshot과 테이블 수 동일성 검증

### QA-004 학습 경로 초기 JavaScript 비용

- 심각도/확신도: 중간 / 높음
- 환경: 프로덕션 빌드 산출물 비교
- 실제 동작: ELK 번들이 학습 경로 라우트 청크에 동기 포함되어 해당 노드가 1,450.23 kB(minified, gzip 449.83 kB)
- 영향: 모바일/저속 기기에서 학습 경로의 코드 다운로드·파싱 비용 증가

- 참고: DAG를 실제 표시할 때 ELK 다운로드는 여전히 필요하다. 이번 변경은 앱 셸과 라우트 평가를 막는 동기 결합을 제거한 것이며 레이아웃 알고리즘은 변경하지 않았다.

## 코드 분석으로 확인한 범위

- 대시보드는 curriculum/catalog/IndexedDB snapshot만 읽고 레슨·문제 본문을 전체 hydrate하지 않는다.
- 레슨 진입 시 선택 레슨의 본문과 해당 문제만 지연 로딩한다.
- 백업 유효성 검사는 기존 DB를 지우기 전에 수행되며, 복원 쓰기는 하나의 Dexie 트랜잭션 안에서 실행된다.
- 첫 제출 UUID 중복은 같은 내용이면 no-op, 다른 내용이면 오류로 거부된다.
- 서비스 워커는 전체 정적 콘텐츠 캐시를 유지하고 설치 요청을 batch 처리한다.

## 수정하지 않은 발견 사항

- Vite는 분리된 ELK 청크가 500 kB를 넘는다는 경고를 유지한다. ELK 자체 교체나 레이아웃 알고리즘 변경은 이번 범위와 회귀 위험에 비해 과도해 수정하지 않았다.
- 여러 탭이 같은 레슨의 서로 다른 단계에서 `saveSession`을 수행하면 마지막 쓰기가 우선한다. 현재 명세는 다중 탭 세션 병합을 보장하지 않으며, 단순 단조 증가 보호는 명시적인 `이전` 기능을 깨뜨리므로 변경하지 않았다. StudyEvent와 XP 중복 방지는 검증했다.
- `docs/TESTING.md`의 “처음에는 3개 트랙만 표시” 문구와 현재 신규 화면의 8개 열린 트랙이 일치하지 않는다. 현재 curriculum의 독립 시작 노드와 실제 구현을 기준으로 기능 결함으로 확정하지 않았으며 문서 정책 결정이 필요하다.
